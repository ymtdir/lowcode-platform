# Git操作ルール

## 重要: ユーザーの明示的な許可が必要な操作

以下の操作は**必ずユーザーの明示的な許可を得てから**実行すること。

### Git操作

- `git commit` - コミットの作成
- `git push` - リモートへのプッシュ
- `git reset` - コミットの取り消し
- `git rebase` - リベース
- `git merge` - マージ
- その他、リポジトリの履歴を変更する操作

### GitHub操作

- `gh pr create` - プルリクエストの作成
- `gh pr merge` - プルリクエストのマージ
- `gh pr close` - プルリクエストのクローズ
- `gh issue create` - Issueの作成
- その他、GitHubリソースを作成・変更する操作

### 破壊的なコマンド

- `rm -rf` - ファイル・ディレクトリの削除
- `npm install` - 依存関係の変更
- `npx` - 外部パッケージの実行
- データベースのマイグレーション
- その他、取り返しのつかない変更を伴う操作

## 推奨される作業フロー

1. コード変更を実装
2. ビルド・テストで動作確認
3. 変更内容をユーザーに報告
4. **ユーザーの許可を得てから**コミット・プッシュ

## 例外: 事前承認されている操作

ユーザーが明示的に「コミットしてプッシュして」「PRを作成して」などと指示した場合のみ、該当する操作を実行可能。

## コミットメッセージ

コミットメッセージは以下の形式を推奨:

```
<type>: <subject>
```

### type

- `feat`: 新機能
- `fix`: バグ修正
- `docs`: ドキュメントのみの変更
- `style`: コードの意味に影響しない変更（空白、フォーマット等）
- `refactor`: バグ修正でも新機能でもないコード変更
- `test`: テストの追加・修正
- `chore`: ビルドプロセスやツールの変更

### 例

```
feat: グループメンバー追加機能を実装
```
